# Phase 1 completion report

Commits `debb0e4`, `bf60da9`, `930c937`. Baseline `9654d99`.

## Implemented

**Golden fixture layer.** Eight synthetic projects in `tests/fixtures/projects`,
written as IR documents, with golden output in `tests/golden` and a harness at
`packages/core/crates/ladx-ir/tests/golden.rs`. Regenerate with
`UPDATE_GOLDEN=1 cargo test -p ladx-ir --test golden`.

Verified by planting a regression rather than by inspection: a converter
emitting `&` instead of `AND` was introduced, the golden caught it on the first
fixture, and it was reverted.

**IR extensions.** `entry_point`, `scan_ms`, and `Tag.field` describing what a
tag is wired to (`FieldDevice`, `IoDirection`, `DeviceKind`). All optional on
the wire; a document written before they existed still loads, which is tested.

**Feature flags.** Eleven flags defined in `ladx-types`, generated into
TypeScript, persisted in `StudioSettings.features`. All off by default.
`Maturity` carries Planned/Experimental/Available/Validated, everything is
Planned, and a test holds it there.

**Vendor connector architecture.** `ladx-vendor` has `VendorConnector`,
`Availability`, `UnusableReason`, `VendorCapabilities`, `VendorStatus` and
`Registry`. Not-installed is an ordinary answer. A panicking connector is
caught and degrades one vendor only.

## Partially implemented

- `Maturity` is defined and carried but nothing displays it yet. It becomes
  visible when the first flag gates something real, in Phase 2.
- Feature flags persist on the desktop only. The web has no store for them yet
  and needs none until a flag gates something there.
- `ladx-vendor` defines the shape. No concrete connector exists; that is
  Phase 4 for Siemens and Phase 2 for Rockwell.

## Not implemented

Everything from Phase 2 onward. In particular the L5X parser is still
name-only, and the two IRs are still unreconciled: this phase made `ladx-ir`
capable of holding the editor's model, it did not move anything onto it.

## Regressions

None. No existing test changed. No route, Tauri command or persisted shape was
renamed or removed. The 51 Tauri commands are untouched.

`biome.json` now ignores `tests/fixtures` and `tests/golden`, which are
generated, in the same way it already ignores `**/generated/**`. Without it the
formatter and the fixture generator rewrite each other's output.

## Security impact

None. No new network call, no new file write outside the existing settings
path, no new dependency. `catch_unwind` in the registry is a containment
boundary, not a new capability.

## Performance impact

## Next recommended phase

Phase 2, one IR and a real L5X reader. It is the phase the whole plan turns on,
and it is now safe to attempt because the golden layer will catch output that
silently changes shape.

Suggested order:

1. Deepen `ladx-parsers::l5x` from names to content, rung logic first.
2. Add L5X fixtures beside the IR ones, and `L5X → IR → L5X` goldens.
3. Conversion reports: EXACT, APPROXIMATE, UNSUPPORTED, PRESERVED, MANUAL
   REVIEW REQUIRED.
4. Only then move Convert onto the Rust IR, behind `vendor.rockwell`, with the
   TypeScript path retired when golden output matches.
